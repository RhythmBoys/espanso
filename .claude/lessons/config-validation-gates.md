# 配置发布验证门禁

## 2026-07-20 — “成功加载”不等于“可以发布”

- 现象：`espanso_config::load()` 可返回 `Ok`，同时携带非空的 `NonFatalErrorSet`；只检查 `Result` 会把解析或校验异常误判为有效配置。
- 原则：任何迁移、原子替换或设置 UI 写入都必须同时检查主错误和非致命错误集合；数据变更路径应采用 fail-closed。
- 模式：先验证当前基线，再把候选文件写入隔离副本，对完整候选配置执行同一加载器验证，最后才原子发布到活动目录。
- 补充：框架加载器未必把跨文件业务冲突视为错误。对本项目的 trigger 唯一性，应额外扫描非托管 YAML，并在候选发布前拒绝冲突。
- 防回归：迁移验证、外部无效 YAML、跨文件重复 trigger 都必须有“最后有效文件字节不变”的测试断言。
